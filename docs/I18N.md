# Internationalization

RecetApp speaks English (`en`) and Spanish (`es`). There is no i18n library: the
layer is small enough to read in one sitting, and it adds no native dependency.

## Where things live

| Piece                                       | Location                                                              |
| ------------------------------------------- | --------------------------------------------------------------------- |
| Message catalogs (flat, dotted keys)        | `apps/mobile/src/shared/i18n/messages/{en,es}.ts`                     |
| `createTranslator` (interpolation, plurals) | `apps/mobile/src/shared/i18n/translator.ts`                           |
| Provider, `useTranslation`, `useI18n`       | `apps/mobile/src/shared/i18n/i18n-provider.tsx`                       |
| Language picker screen                      | `apps/mobile/src/app/language.tsx`, `shared/i18n/language-picker.tsx` |
| `Language` type shared with the API         | `packages/contracts/src/language.ts`                                  |

## Rules

- `en.ts` is the source of truth for keys. `es.ts` is typed against it, and a test
  fails if either catalog has a key or a `{placeholder}` the other lacks.
- A count-dependent message has `key_one` and `key_other`; call `t('key', { count })`.
- Identifiers are never translated: categories (`dairy`), meal slots (`dinner`),
  units, difficulty and staples (`cooking oil`) are stored and sent in English.
  Only their labels come from the catalog, at render time. Stored data is not
  migrated.
- Dates are formatted from the ISO parts and the catalog, not `Intl`, so they stay
  timezone-free.
- Spanish copy is neutral and uses the imperative ("Agregar", "Guardar").
- A component rendered without a provider falls back to English.

## Language choice

The choice is stored in the settings table (key `language`). With nothing stored,
the app shows the picker before the tabs (`Stack.Protected` in `app/_layout.tsx`).
The device locale only decides which option is highlighted as suggested. The
picker can be reopened from the Pantry header.

## AI-generated text

The mobile client sends `language: 'en' | 'es'` with every suggestion, recipe and
meal-plan request. The API validates it with zod and defaults to `'en'` when it is
absent, so builds that predate the setting keep working. The Gemini prompt asks
for titles, summaries, ingredient names and steps in that language; response
schemas and enum values (`unit`, `difficulty`) are identical for every language.

Staples are matched against ingredient names by text, so when the language is not
English the client also sends the staple's name in that language (`sal` next to
`salt`).
